# Pointlabs One Foundation and Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the testable Flask/PWA foundation, configured designation catalog, and first-login administrator account for Pointlabs One.

**Architecture:** A Flask application factory builds registered blueprints and extensions from environment-backed settings. SQLAlchemy models stay in focused domain modules, Flask-Migrate owns schema evolution, and a CLI seed command creates the designation catalog plus one temporary administrator. Responsive Jinja templates share a branded shell, with a PWA manifest and service worker layered on top.

**Tech Stack:** Python 3.12+, Flask, SQLAlchemy, Flask-Migrate, Flask-Login, Flask-WTF/CSRF protection, Werkzeug password hashing, Pillow, pytest, Playwright, SQLite (local), MySQL-compatible configuration, vanilla HTML/CSS/JavaScript.

---

## Target file structure

```text
app/
  __init__.py                 # Application factory and extension registration
  config.py                   # Local/test/production configuration from env vars
  extensions.py               # db, migrate, login manager, csrf instances
  models/
    __init__.py               # Model exports
    common.py                 # Timestamp mixin and audit-friendly helpers
    organization.py           # Entity, Location, Department, Designation
    user.py                   # User and EmployeeProfile models
  auth/
    __init__.py               # Authentication blueprint
    routes.py                 # Login, logout, forced password change
    forms.py                  # Validated auth forms
  main/
    __init__.py               # Main blueprint
    routes.py                 # Signed-in landing page
  services/
    seed.py                   # Seed catalog and initial admin idempotently
  templates/
    base.html                 # Theme-aware responsive shell
    auth/login.html
    auth/change_password.html
    main/dashboard.html
  static/
    css/app.css               # Tokens, light/dark theme, mobile layout
    js/app.js                 # Theme persistence and install prompt behavior
    js/service-worker.js      # Offline shell cache
    manifest.webmanifest
  cli.py                      # Flask CLI commands
migrations/                   # Generated by Flask-Migrate; never hand-edit revisions
tests/
  conftest.py                 # Test app, client, isolated database fixtures
  test_config.py
  models/test_organization.py
  models/test_user.py
  services/test_seed.py
  auth/test_login.py
  main/test_dashboard.py
  browser/test_shell.py
requirements.txt
.env.example                  # Keys only; no values/secrets
run.py                        # Local Flask entry point
```

## Configuration contract

- `SECRET_KEY`: required outside tests.
- `DATABASE_URL`: SQLite development URL or MySQL production URL.
- `TEST_ADMIN_USERNAME`: defaults to `admin` only for local seed use.
- `TEST_ADMIN_PASSWORD`: local-only user-supplied temporary password; never commit it.
- `APP_ENV`: `development`, `testing`, or `production`.
- `SMTP_*`: reserved for the later mail milestone; no real mail send in this foundation.
